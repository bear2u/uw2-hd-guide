# 다이어그램 흐름 모션 규칙

rossark-motion-skill(MIT, rossark0)의 원칙 중 다이어그램 재생에 해당하는 것만 추려 플레이어에 적용한 방식을 적었다. 플레이어를 고칠 때 이 규칙을 깨지 않는다.

| 원칙 (rossark) | 플레이어에서 |
| --- | --- |
| 순간이동 금지: 모든 것은 보간한다 | 선은 그려지고, 패킷은 선을 따라 이동하고, 색은 섞여서 돌아온다. 어떤 요소도 갑자기 바뀌지 않는다 |
| 이동은 ease-in-out, 등장은 ease-out | 선 그리기·패킷 = `bezier(0.77, 0, 0.175, 1)`, 라벨·화살촉·노드 등장 = `bezier(0.23, 1, 0.32, 1)` |
| 한 장면에 주된 동작은 하나 | 한 번에 비트 하나만 활성. 이전 비트의 강조는 서서히 꺼진다 |
| opacity는 나타나고 사라질 때만 | 반투명으로 흐리게 두는 상태가 없다. 아직 안 온 요소는 안 보이고, 지나간 요소는 완전히 보인다 |
| 무에서 나타나지 않는다 (scale 0.9–0.97부터) | 등장은 scale 0.92→1. 패킷 같은 작은 점만 예외 |
| 레이아웃은 움직이지 않는다 | SVG 배치는 그대로. 움직임은 그룹 안의 transform·마스크·색뿐 |
| 다이어그램은 원샷 draw-on, 마지막 프레임 = 데이터 | 끝까지 재생하면 정적 SVG와 똑같은 그림에서 멈춘다 |
| 모션 줄이기 = 정지 | `prefers-reduced-motion: reduce`면 완성 프레임으로 시작하고, 단계 이동은 애니메이션 없이 바로 간다 |
| 보이지 않으면 멈춘다 | 탭이 숨겨지면 `requestAnimationFrame`을 끊고, 돌아오면 이어서 재생 |
| 시계는 장면당 하나 | `render(t)` 하나가 모든 요소를 계산한다. 스크럽·단계 이동이 중간부터 이어져도 튀지 않는다 |
| 움직임마다 프레임을 충분히 | 가장 짧은 선도 480ms 이상, 등장 220ms. 30fps에서 깜빡이지 않는 길이 |
| 비대칭 타이밍 | 그리기(이동)는 길고, 도착 표시(라벨·화살촉)는 짧다. 거절은 읽을 시간을 260ms 더 준다 |

## 인터페이스 쪽 (rossark 7장)

- 버튼 누름은 scale 0.97, 120ms ease-out.
- 재생 중 따라가기 스크롤은 현재 비트가 화면 밖일 때만, 부드럽게 한다.
- 중간에 다시 조작해도(스크럽, 단계 이동) 현재 값에서 이어간다. 처음부터 다시 시작하지 않는다.
